# Brand requirements and candidate resources

First identify whether the user or current project explicitly requires a brand, template, font, palette or visual system. Those requirements are binding for the selected scope. A user's request to revise that identity changes only the authorized constraints.

When no identity is selected, NERO resources are candidates alongside suitable outside references and an original project direction. Do not turn a local default, an approved library style or a past preference into a compulsory house style.

## Local candidate locations

- Brand profile: `$NERO_DESIGN_TEAM_HOME/brand/brand-profile.json`
- Layout candidates: `$NERO_DESIGN_TEAM_HOME/brand/master-layouts.json`
- Cover, chart and PPT guidance: `brand/cover-system.md`, `brand/chart-style.md`, `brand/ppt-master.md` under the same root.
- Tokens and templates: current Registry locations; select by inspected fit rather than a reuse quota.

Inspect the actual mark, palette/type preview or template page before using it. Record the asset's role, adjustments, version and rights state in the project style record. Coordinate chosen resources with the whole composition using M04 in [method cards](design-methods.md).

## Non-negotiable boundaries

- Do not invent a brand identity or logo that falsely represents an entity.
- Honor quarantine, placeholder and reference-only states; an unavailable optional mark permits a no-mark design.
- Preserve readability, exact facts, functioning controls and explicit user brand requirements.
- Approval of a style version does not establish its suitability for this task; approval of the project design does not automatically promote a global style.
