# Reference exploration and composition

This is part of the director Skill, not another controller or search service. The model chooses the exploration branch from the task; users need not set a technical switch.

## Automatic branch

| Task evidence | Search approach | Direction requirement |
|---|---|---|
| Continue a design, add a small component in an existing system, follow a named template, make a clear local repair | Inspect the current artifact; search local references only when needed. Expand online for missing material, poor fit or repeated attempts without improvement | Preserve the selected identity/content; a clear bounded change needs no search, direction set, new manifest, separate trial or tutorial example |
| New overall identity/layout, request for freshness, dislike/rejection of current proposals, or explicit broad redesign | Dual search: local library plus internet; search for different methods, including other media | Important new work gets 2–3 substantively different directions; retain one independent of existing preset aesthetics within the task's constraints |
| Audit | Inspect current renders and appropriate comparisons; use web comparisons when the diagnostic question needs them | Report findings/directions; do not produce replacements or register assets |

Explicit no-network, a locked template or material restrictions take precedence. A broad search cannot silently replace a selected brand. A request to change the existing direction is evaluated against its permitted change scope, not rejected because the old style was once approved.

## Actual tools and evidence

Check tools exposed in the current session, then use a matching capability. Record a failed/unavailable route; do not invent a tool call or say a preview was viewed from metadata alone.

| Need | Available route in Codex | Evidence needed |
|---|---|---|
| Search local styles/assets/cases | `nero_design_get_registry` with `include_library`, `search`, `tags`/`use_case_tags`; use `style_id`/`style_version` for an exact version. `nero_design_get_case_snapshot` locates existing cases. If MCP is unavailable, read the same Registry and referenced files locally. | IDs/versions and relevant source/preview locations; registry names/tags alone are not a visual review |
| Discover outside references | The web tool's `search_query`; search by the missing method plus subject/audience. `image_query`, when exposed, can locate visual candidates. A browser search is a fallback when available. | Original source URL, selected page/image, what method it may contribute; do not send client secrets or unpublished text in queries |
| View a local preview | `view_image` for actual supported local image files; open a source page/document in the relevant viewer when needed. Resolve Registry previews to real paths first. | Actual pixels/pages seen, their version and the inspected detail |
| Inspect a web reference | Open the original page; use the available browser plugin/in-app browser for screenshots, or a returned image display for the actual image. A text-only fetch is useful context but is not image inspection. | Viewed image/page and the observed visual method; snippets, filenames and alt text do not count |
| Render and compare the trial | Existing output engine and the medium's preview tool. Browser interaction uses the enabled browser surface; scripts use the installed, policy-approved bundled headless runtime and close it in `finally`. Static diagrams may use their deterministic renderer. | Current trial and before/after render at the same relevant size; never launch/install a missing runtime silently |

If a required preview cannot be opened, keep it `preview_uninspected` and do not claim it supports the chosen design. Try a usable alternative. If online access is unavailable during dual search, state that gap and continue with the inspected candidates and an original direction; do not describe that as completed internet exploration or full reference coverage.

## From references to a trial

Use this sequence when reference exploration or a new composition is actually needed. It does not add preparation paperwork to a clear local repair.

1. Search by the missing operation, such as hierarchy in editorial pages, compact status in industrial instruments, or motion for object continuity. The reference need not be the same product category.
2. Inspect the relevant part at meaningful scale. Record what to borrow (hierarchy, grouping, rhythm, type relationships, material, interaction) and what to exclude (brand identity, unrelated content, unsupported behaviors or restricted assets).
3. Propose directions that change composition or experience, not just palette. Explain the intended effect, actual reference contribution and fit to this audience/task.
4. For a new or materially recombined visual system, maintain a small style record inside the existing project manifest or design spec. Record: `intent`, `locked_constraints`, `exploration_mode/reason`, `reference_candidates` with provenance and viewed-preview status, `selected_direction`, `asset_roles`, `combination_rules`, `parameters`, and `trial/qa` locations. Use one existing record when possible, not a parallel database or mandatory family of sidecars.
5. Give each chosen asset a job and choose a dominant direction. Coordinate typography roles, spacing, colors and material/motion strength; do not paste whole style packages together. A project may use few or no local assets when inspected alternatives fit better.
6. Render a representative slice, diagnose the most important problem and revise locally. Preserve the same content and target size for a meaningful before/after comparison. Stop a tactic that yields no improvement; change the hypothesis or search method instead of accumulating decoration.

## Candidate retention

New references enter the project-local candidate list first, including `preview_inspected` or its explicit gap. This is the candidate pool for the current task, not approval or automatic global asset intake. Eligible independent local assets may later enter the existing revision-checked asset intake path; source pages, methods and complete cases retain their proper categories and rights restrictions.

After NERO confirms the exact useful combination, save it through existing style versioning as a new version. Preserve old styles and their history. A successful render, score or library save does not itself grant mature-style approval.
